
## Requisitos Funcionais

| ID | Módulo / Categoria | Requisito Funcional |
| --- | --- | --- |
| RF01 | Login | O sistema deve permitir a autenticação de usuários previamente cadastrados por meio da inserção de credenciais válidas. O sistema ficará responsável por validar esses dados. Em caso de falha (credenciais incorretas ou usuário inexistente), o sistema deve informar o usuário e oferecer a opção de recuperação de senha. |
| RF02 | Cadastro | O sistema deve permitir a criação de dois tipos de usuários (Nutricionista e Comum) com os campos do usuário Nutricionista sendo o NOME COMPLETO, DATA NASC., CRN, CEP DA CLÍNICA/CONSULTÓRIO, USUÁRIO e SENHA. Já para o Usuário Comum terá os campos NOME COMPLETO, DATA DE NASC., USUÁRIO e SENHA. Os requisitos dos campos são: **NOME:** Até 100 caracteres (permitir apenas letras e espaços); **DATA NASC:** Formato padrão de exibição DD/MM/AAAA e bloquear datas futuras; **CRN:** Até 10 dígitos e exibir o formato CRN-x xxxxx; **CEP:** Até 8 dígitos (somente números) e a partir do CEP demonstrar Rua, Número, Bairro e Cidade; **USUÁRIO:** Até 50 caracteres (permitindo apenas letras, números, "." e "_"); **SENHA:** Até 50 caracteres, com o mínimo 8 caracteres e exigindo pelo menos uma letra maiúscula, uma minúscula. Sendo também aceitos caracteres especiais como @, # e $. |
| RF03 | Metas e Perfil Biométrico | O sistema deve permitir que o usuário configure e faça a gestão do seu perfil biométrico e metas nutricionais. No primeiro acesso (ou posteriormente nas configurações), a aplicação deve solicitar informações biométricas como: **SEXO:** Até 1 caracter (sendo mostrado as opções válidas M e F); **IDADE:** Int com 1 byte e não permitindo valores negativos; **ALTURA:** Até 3 dígitos, com a medida em centímetros; **PESO ATUAL:** Até 5 dígitos com 2 casas decimais; **PESO OBJETIVO:** Até 5 dígitos com 2 casas decimais; **GRAU DE ATIVIDADE FÍSICA:** Permitir 3 caracteres com cada um sendo equivalente a um grau de atividade. Com base nestes dados, o sistema deve ser capaz de calcular automaticamente a meta diária de consumo de calorias. Além disso, o sistema deve permitir que o usuário edite manualmente a sua própria meta calórica diária em qualquer momento. |
| RF04 | Cálculos e Informações Nutricionais | O sistema deve processar os dados biométricos do usuário (como peso, altura, idade e nível de atividade) utilizando equações científicas preditivas para calcular o metabolismo basal e o gasto energético total. Com essas métricas exatas estabelecidas, a plataforma cruza as informações com bases de dados confiáveis (TBCA). Com isso, é viabilizada a criação ágil de cardápios, o registro diário de refeições e a contagem precisa e automatizada dos macronutrientes consumidos. |
| RF05 | Gestão de Cardápios e Refeições | O sistema deve fornecer uma gestão completa da alimentação diária do usuário, garantindo que a tela principal de cardápio do dia seja facilmente acessível a partir de qualquer outra tela do aplicativo. A aplicação deve permitir a criação e organização de refeições padrão (como café da manhã, almoço, café da tarde e jantar). O usuário pode adicionar novas refeições customizadas ou remover refeições existentes do seu cardápio diário. O sistema deve permitir o registro de consumo de água, quantidade de sono do paciente. Será enviado ao paciente um widget em seu smartphone para que seja feita a inserção desses dados. Para a composição dos pratos, o sistema deve permitir que o usuário monte uma refeição pesquisando alimentos por nome em um banco de dados *offline*. Durante essa montagem, deve ser possível adicionar novos alimentos, editar as quantidades consumidas e remover itens indesejados. Por fim, o aplicativo deve permitir que o usuário salve esse cardápio customizado montado e acessar a hora que quiser. O sistema deve permitir a geração de relatórios altamente customizados dos planos alimentares em formato PDF. |
| RF06 | Consulta de Alimentos | O sistema deve permitir que os usuários busquem itens e suas propriedades em um amplo catálogo integrado à Tabela Brasileira de Composição de Alimentos (TBCA). Para garantir uma experiência ágil na montagem de pratos, o sistema realiza buscas otimizadas com tempo de resposta inferior a dois segundos. Além disso, a funcionalidade conta com um mecanismo de segurança offline (fallback) que armazena localmente os 200 alimentos mais consumidos no Brasil, assegurando o registro de refeições mesmo sem conexão à internet ou em caso de falha da API principal. |
| RF07 | Chat Nativo | O sistema deve possuir uma forma de interação textual direta entre pacientes e seus respectivos nutricionistas. Com a busca de usuários vindo por nome completo ou de usuário e também tendo um campo mostrando suas últimas conversas. O módulo deve permitir o envio de mensagens, fotos e PDFs. |
| RF08 | Ecossistema Nutricionistas | O ecossistema destinado aos nutricionistas funciona como uma ferramenta de CRM clínico e gestão, oferecendo um painel de controle (dashboard) exclusivo para o perfil profissional. Nesse ambiente, o nutricionista consegue vincular seus pacientes. Além disso, o sistema deve permitir que os usuários avaliem e deixem comentários (*reviews*) nos perfis dos nutricionistas. E também permitir que o usuário comum pesquise por nutricionistas cadastrados na plataforma com base na sua localização geográfica. |
| RF09 | Gerência de Paciente | O nutricionista deve poder acessar e controlar quais informações o paciente poderá ter acesso e visualizar os dados que o paciente incluiu sobre seu consumo (água e alimentação) e sono. Ele poderá alterar campos como: **META DO USUÁRIO; GERENCIAR PLANOS ALIMENTARES.** Ele poderá inserir informações como: **NOTAS CLÍNICAS; CRIAR NOVOS CARDÁPIOS.** Ele poderá PRESCREVER ATESTADO para o paciente, sendo que ao clicar no botão de criação, o sistema deverá enviar um documento base que possuirá todos os campos com as informações já cadastradas no sistema, para que o nutricionista possa completá-lo, assiná-lo (manualmente via mouse ou por uma API com a assinatura do [GOV.BR](https://gov.br)) e enviar para o paciente em formato PDF. |
| RF10 | Inserção de Dados de Bioimpedância | O sistema deve permitir que, após a coleta dos dados do exame de bioimpedância, o nutricionista possa inserir essas informações em um documento que mostre um detalhamento da composição corporal do paciente. O nutricionista poderá disponibilizar o arquivo ao seu paciente quando necessário, ou seja, o acesso ao laudo de bioimpedância ficará a critério de disponibilização do nutricionista. Sendo em partes ou completa. |
